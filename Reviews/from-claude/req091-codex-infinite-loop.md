## 실측 증거 (오케스트레이터, WebGL 로컬)

- 스테이지 1 시작 후 ~10초 지점에서 화면이 완전 정지 (두 스크린샷 픽셀 동일).
- requestAnimationFrame 600ms 동안 **0프레임** = 브라우저 메인 스레드 잠김 =
  C# 코드 무한 루프 (크래시/예외 아님 — ErrorOverlay·콘솔 예외 없음).
- 다른 세션에서는 110초+ 동안 돌다가(적 스폰·이동 정상) 룸이 끝나지 않았다 —
  아마 그 세션도 결국 같은 지점에서 얼었을 것.
- 시드는 타이틀 TickCount 기반(무작위). `DeterminismAudit -- 12345 3 30000`은
  main에서 정상(9/9 rooms) — **시드/상태 의존 루프**다.

## 의심 지점 (REQ-090 신규 코드)

- `BoundaryWaitsForResidualHostileBulletsToExit` 계열의 "잔여물이 나갈 때까지 대기"
  로직 — 조건이 영원히 만족되지 않는 상태(예: 계속 재생성되는 무언가, 정지 적탄,
  경계 안 잡히는 엔티티)가 있으면 룸이 영원히 안 끝나거나 내부 while이 돈다.
- ScrollX baseOffset 승계가 스폰/컬링/세그먼트 스케줄 비교식과 어긋나 while 스캔이
  전진하지 못하는 경우.
- 정리 구간 창 계산이 특정 룸 길이/틱에서 역전(음수 창)되는 경우.

## 요구

1. **워치독 시드 스캔으로 재현하라**: 시드 0~255 × 풀런(또는 스테이지1 완주)을
   Step당 연산 상한 워치독과 함께 돌려 **행이 걸리는 시드를 찾아라**. 재현 시드
   최소 1개를 보고서에 명시.
2. 근본 원인 수정. "대기" 류 로직에는 **결정론적 상한**(최대 대기 틱 후 강제 진행)을
   반드시 넣어라 — 시뮬레이션에 무한 대기는 존재해선 안 된다.
3. 회귀 테스트: 재현 시드 고정 테스트 + 시드 스캔 스모크(예: 64시드 스테이지1 완주가
   틱 상한 내 종료).
4. Assets/Tests는 Unity NUnit 호환(Assert.Multiple 금지), Core 심벌 public.
