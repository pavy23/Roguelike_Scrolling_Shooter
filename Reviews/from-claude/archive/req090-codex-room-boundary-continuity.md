# REQ-090 (CODEX): 룸 경계 연속성 + 중간보스 침하 버그 (사람 3차 재교정)

너는 CODEX = SIMULATION 담당이다. 작업 디렉토리 wt-sim, 시작 전 `git merge main`.

## 배경 — 왜 두 번 고쳤는데도 "끊기듯" 나오는가 (오케스트레이터 진단)

REQ-082/085는 **한 배틀 안의** 보스 등장 시퀀스를 고쳤다. 그런데 실제 구조는
Opening(room1) → MidBoss(**room2 = 별도 BattleSim**) → StageBoss(**room3 = 별도 BattleSim**)다.
사람이 보는 끊김은 **룸 경계의 하드컷**이다:

1. 경계 순간 이전 룸의 적·탄·캡슐이 통째로 증발한다 (새 sim은 빈 필드에서 시작).
2. 새 배틀의 ScrollX가 0에서 다시 시작해 **배경 패럴랙스가 점프**한다.
3. 그 직후 보스가 활강해 들어와도 이미 컷이 눈에 박힌 뒤다.

배틀 내 스폰 억제·자연 퇴장은 경계와 무관하게 동작해 헛수고였다. 이 진단을 검증하고
(룸 경계 전후 관측값으로), 틀렸다면 실제 원인을 찾아라.

## A. 룸 경계 연속성

1. **직전 룸 끝을 비워라**: 보스 룸(중간보스·보스·히든 보스)에 선행하는 룸의 마지막
   ~60틱에 신규 스폰 억제 + 잔여 적 자연 퇴장(REQ-085 로직 재사용)을 걸어, 경계
   시점에 필드가 이미 자연스럽게 비어 있게 하라. 잔여 적 강제 증발은 경계에서
   더 이상 일어나지 않아야 한다 (남았으면 이월하거나 퇴장 완료를 몇 틱 기다리는
   쪽 — 결정론 유지 조건에서 네가 판단).
2. **ScrollX 연속**: 다음 배틀이 이전 배틀의 최종 ScrollX에서 이어지게 하라
   (오프셋 승계). Presentation 패럴랙스는 sim.ScrollX를 그대로 소비하므로 이것만
   이어지면 배경 점프가 사라진다. GetScrollXAtTick 순수식이니 base offset 하나면 된다.
3. 캡슐/폭탄 픽업의 경계 증발도 정리 (마지막 60틱 드롭 억제 or 이월 — 네 판단).
4. 리플레이/서스펜드 재현 검증. 스키마 버전 영향 판단 명시.

## B. 중간보스 침하 (사람: "일정 시간 이후 아래에만 머무는")

중간보스가 시간이 지나면 화면 하단에 붙어 안 올라온다. 의심: REQ-082 B의 페이즈
전환 위상 연속화가 전환마다 앵커를 아래로 끌어내리는 누적 드리프트, 또는 하단
클램프 후 앵커 미복원. 같은 시드 장시간 시뮬로 y 궤적을 뽑아 원인을 확정하고,
사인 호버가 **스폰 앵커 주변에서 지속 진동**하도록 고쳐라. 회귀 테스트:
전 페이즈에 걸쳐 y의 이동 평균이 앵커에서 일정 범위 이상 이탈하지 않을 것.
