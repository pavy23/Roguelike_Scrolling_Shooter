## REQ-170 — 하이브 최종 페이즈 Brood 복구 (유도 0)

### 배경

REQ-160에서 유도 제거를 위해 최종 페이즈의 Brood 시그니처를 **통째로 삭제**했다.  
그 결과 유도뿐 아니라 **텐타클 소환까지 사라졌다**.

### 데이터 (최종 페이즈 `hpThreshold: 0.333`만)

| 필드 | 값 | 비고 |
|---|---|---|
| `signaturePatternId` | `brood` | 복구 |
| `signatureSpawnEnemyId` | `hive_tentacle` | 필수 |
| `signatureHomingTurnLutSlotsPerTick` | **0** | 비행 중 선회 없음 → 예고 종료 조준 고정 직진 |
| ways / bulletSpeed / mine* / spiral interval | **REQ-160 이전 유지** | 24 / 9 / 2.5 / accel 2 / tel 28 등 — 속도 손대지 않음 |

중간 페이즈(`0.667`) brood·homing 1은 그대로.

### Core 대기

현재 트리의 `BossPhase` 생성자 (`IStageGenerator.cs`):

```
Brood signatures require a spawn enemy id and positive homing turn rate.
→ signatureHomingTurnLutSlotsPerTick < 1 이면 거부
```

요청대로 **0을 데이터에 넣었고**, 파서가 거절한다.  
오케스트레이터 측 “0 허용” 수정이 **아직 이 worktree / main에 반영되지 않았다**.

**필요 수정 (Core 한 줄 수준)**: Brood 시 spawn id만 필수, homing은 `>= 0` 허용  
(`0` = 스폰만, 비행 중 선회 없음).

이 한 줄이 들어가면 repository 파싱 실패 36건이 해소될 것으로 본다.

### BalanceSim 게이트 (수정은 오케스트레이터 몫)

```

```

→ `5.625`는 **상한 4.0 초과**. Core 파싱 재개 후 예상 메시지:

`FAIL 116: leviathan ... railgun fullHalfWidth 1.2–4.0 / endOffset ≤ -30.`

제안: 상한을 `>= 5.5 && <= 6.0` 또는 `<= 6.0`으로 상향 (절반 두께 시그니처).

## REQ-173 — 브루드마더 P3: 전방 5줄기 부채 레이저

### 설계

- **동시 발사** (같은 cycle/telegraph) → 부채꼴 한 방 그림.
- 예고 **3.0s** (180t), cycle **7.0s** (420t) → 빔 구간 ~4.2s 후 **~2.8s 빈 구간**.
- 각도는 `endOffset` 비율 (Core가 화면 끝까지 연장).

| 파츠 | 각도 | endOffset | fullHalfW |
|---|---:|---|---:|
| `maw` | 0° | (−32, **0**) | 1.75 (중앙 주력) |
| `sac_left` | +15° | (−32, **+8.57421875**) | 1.25 |
| `sac_right` | −15° | (−32, **−8.57421875**) | 1.25 |
| `tentacle_left` | +30° | (−32, **+18.4765625**) | 1.25 |
| `tentacle_right` | −30° | (−32, **−18.4765625**) | 1.25 |

요청 비율 (−1, ±0.268 / ±0.577)에 대한 **1/256 격자 근사**  
(`8.57421875/32 ≈ 0.2679`, `18.4765625/32 ≈ 0.5774` → 실측 각도 ±15.0° / ±30.0°).

`sac_lower` 스폰·`heart_core` 방사탄은 유지.
