## REQ-166 — 한 번 부순 부위가 다시 살아난다

### 문제

사람: 파괴한 부위가 사라지지 않고 다시 생기는 듯함.

원인: `boss_broodmother` 의 `tentacle_left` / `tentacle_right` 에  
`regenerationTicks: 900` (15s @60fps) 이 걸려 있었다.  
부순 것이 돌아오면 “어느 부위를 부쉈는지” 화면에서 셀 수 없다.

### 조치

두 촉수에서 **`regenerationTicks` 필드를 삭제** (기본 0 = 재생 없음).

| 파츠 | 전 | 후 |
|---|---|---|
| tentacle_left | regen 900 · hp 1500 | **regen 없음** · hp 900 (REQ-167 스케일) |
| tentacle_right | regen 900 · hp 1500 | **regen 없음** · hp 900 |

`GameData/waves.json` 전체에서 `regenerationTicks` **0건** (다른 보스에 신규 재생 없음).

### 근거

- 다른 보스(레비아탄·전함 등)는 원래 재생 없음 — 히든만 예외였다.
- 재생은 “지구력 시험”을 늘리고 파괴 피드백을 지운다. 히든 난이도는 HP·패턴으로 잡는다.

## REQ-168 — 전함이 너무 허약하고 2막이 심심하다

### 측정 근거

헤드리스: 최대 파워로 전함 3막 **80초** 완주 — 너무 빠름.  
사람: 각 페이스 HP 2배 + 2막 함저 포탑 2→4 + 움직임 자연스럽게.

### 1. 파츠 HP ×2 + 함저 2문 추가

| 파츠 | 구 HP | 신 HP | 역할 |
|---|---:|---:|---|
| engine | 1000 | **2000** | 1막 게이트 |
| turret_a / b (갑판) | 700 | **1400** | 1막 |
| turret_c / d (함저) | 1200 | **2400** | 2막 |
| turret_e / f (함저 **신규**) | — | **2400** | 2막 |
| core | 14800 | **29600** | 3막 |
| **합 / boss.hp** | 19600 | **44000** | |

**총 HP가 39,200이 아니라 44,000인 이유**  
요청 문안 “19,600 → 약 39,200” 은 **기존 파츠만 ×2** 한 값.  
함저 2문 → 4문으로 늘리면서 신규 포탑을 강화된 함저 단가(2400)로 넣었기 때문에  
+4,800 (2400×2) → **44,000**.  
막별 격파량:

| 막 | 구 | 신 | 배수 |
|---|---:|---:|---:|
| 1 (engine+a+b) | 2400 | **4800** | ×2 |
| 2 (함저) | 2400 (2문) | **9600** (4문) | ×4 |
| 3 (core) | 14800 | **29600** | ×2 |

이론 pure ST @720 DPS: 전 61.1s / full-eff 23.4s / wall≈60.8s  
(구 순수 ST ~27s 대 · 80초 전격파 체감 완화 방향).

### 2. 함저 4문 — 용골 배치 + 주기 어긋남

용골선 보간 (REQ-157 실측 x=−4/−8 기준, 1/256 격자):

`keelY(x) = −6.625 − 0.203125·(x+4)`  
`offsetY = keelY + halfHeight(1.5)` — 파츠 바닥 = 용골.

| id | offsetX | keelY | offsetY | cycle | telegraph |
|---|---:|---:|---:|---:|---:|
| turret_e (신규) | **−2.0** | −7.03125 | **−5.53125** | **240** | 56 |
| turret_c | −4.0 | −6.625 | −5.125 | **200** | 48 |
| turret_f (신규) | **−6.0** | −6.21875 | **−4.71875** | **260** | 60 |
| turret_d | −8.0 | −5.8125 | −4.3125 | **220** | 52 |

- 레이저: 기존과 동일 수직 `(0,+14)→(0,−16)`, damage 2, fullHalfW 0.875  
- 주기 **200 / 220 / 240 / 260** — 4문이 동시에 점화되지 않도록 어긋남  
- lifetime ≤ cycle (e: 56+8+50+12=126 ≤ 240, f: 60+8+50+12=130 ≤ 260)

`hull.partIds` = `["turret_c","turret_d","turret_e","turret_f"]`.

코어 오프닝 ways: base 9, −2/포탑, min 3  
→ 4문 전멸 시 9−8=1 → **min 3 클램프** 유지 (REQ-111 구조 유지).

### 3. 움직임 — travel 연장 (순간이동 없음)

Core `WarshipEncounter.AnchorOffsetY` 는 **정수 선형 보간**만 지원  
(`from + delta * elapsed / travel`). 가속 곡선·다구간은 데이터만으로 불가.

| 그룹 | 전 travel | 후 travel | 시간 @60fps | 비고 |
|---|---:|---:|---:|---|
| stern | 0 | 0 | — | 등장 고정 |
| hull (↑ +3.0) | 120 (2.0s) | **240 (4.0s)** | ΔY 7.5u → **1.875 u/s** | 어색한 상승 완화 |
| bow (→ 0) | 120 (2.0s) | **180 (3.0s)** | ΔY 3.0u → **1.0 u/s** | 중앙 하강 여유 |

`anchorOffsetY` 값 자체(−4.5 / +3.0 / 0) 는 REQ-160 정렬 유지 — “덜 튀는” 것은 **속도**로 해결.
