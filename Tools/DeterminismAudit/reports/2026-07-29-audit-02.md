## 2. 보상 상한 경계와 RNG 스트림 격리

상한 1회의 고가중치 보상 1개와 동일 효과의 무제한 fallback 4개로 전용
카탈로그를 구성했다. 시드 0~255를 모두 검사했으며 256개 모두 다음 경로
비교 조건을 충족했다.

1. 경로 A는 스테이지 1에서 상한 보상을 선택해 스테이지 2 후보 풀에서
   제외한다(후보 풀 4개).
2. 경로 B는 스테이지 1에서 동일 효과 fallback을 선택해 스테이지 2에서
   상한 보상을 유지한다(후보 풀 5개).
3. 스테이지 2에서 A는 fallback, B는 상한 보상을 선택해 효과와 이후
   eligibility를 다시 합류시킨다.
4. 두 경로의 스테이지 2/3 전체 전투 상태 해시와 스테이지 3 보상 후보
   순서 전체를 비교한다.

결과:

- 256/256 시드에서 상한 도달 경로의 스테이지 2 후보에 상한 보상이 없음
- 256/256 시드에서 미도달 경로의 스테이지 2 후보에 상한 보상이 있음
- 후보 풀 4 대 5인 스테이지 2의 전투 상태 해시 일치
- 경로 합류 뒤 스테이지 3 전투 상태 해시 일치
- 경로 합류 뒤 스테이지 3 보상 후보 ID/순서 일치
- 각 경계 trace 자체를 다시 실행한 결과도 일치

구조 검토 결과도 실행 결과와 일치한다. `RunManager`는 보상 생성마다
`ResetForked(runSeed, RewardSelectionStream, StageIndex)`를 호출하고 전투는
별도 `BattleSimulationStream`을 사용한다. 따라서 후보 풀 크기와
`NextBelow` rejection 횟수가 시드/경로별로 달라져도 해당 스테이지의 보상
선택 안에서만 끝나며, 다음 스테이지나 전투 스트림 상태를 이동시키지
않는다.

- `System.Random`, `UnityEngine.Random`, `Guid.NewGuid()`: 없음
- `DateTime.Now/UtcNow`, `Environment.TickCount`, 환경 변수, Stopwatch,
  thread/task 시간 의존: 없음

현재 트리의 기존 예외도 확인했다.

- `MetaProgression.CarryFraction`과 `Rng.NextDouble/NextBool`의 `double`은
  2026-07-28 최초 구현부터 존재하며 이번 변경에서 유입되지 않았다.
- `SegmentStageGenerator`의 `Dictionary<long,bool>`은 2026-07-28부터
  존재하는 memoization cache다. `TryGetValue`/`Add`만 사용하고 열거하지
  않으므로 순서 의존이 없다.

  전투 누적 계산에 부동소수점으로 전달되지 않는다.
